# 10 — Change History

작업 경과를 시간순으로 짧게 남긴다. 상세 스펙은 `docs/0X-*.md`에 둔다.

## 2026-09-22 — 앱 단순화: 로그인 → 웹뷰 + 단축키 2개

1단계 스캐폴딩(3-모드 캡처, 로컬 Gallery, 단축키 커스터마이징 Settings)을 `개발 가이드라인.md`(Dochi 제품 스펙)에 맞춰 대폭 걷어냈다.

- 전역 단축키를 `⇧⌘1`(생성) / `⇧⌘2`(완료) 두 개로 축소 (`CAP-2`). 항상 영역 드래그 캡처만 사용.
- 로그인 후 메인 화면을 전체화면 웹뷰(`https://www.google.com` 플레이스홀더)로 교체. 실제 대시보드 URL은 추후 연결.
- 캡처는 로컬에 남기지 않고 임시 파일로만 존재, `CaptureApiService`를 통해 서버로 업로드 시도 후 즉시 삭제. Dochi 캡처 엔드포인트가 아직 없어 `baseUrl`은 비워두고 스텁 상태로 둠 (`API-3`).
- Gallery, Settings(단축키 에디터 포함) 화면 전체 삭제 — 단축키 변경 기능은 Non-goal.
- 로그인은 실제 인증 없는 플레이스홀더(버튼 하나로 통과). 세션 상태만 로컬에 영속화.

로드맵상 이 작업이 **2단계 — 코어 연동**의 시작점이다. 남은 일: 실제 로그인(딥링크 인증, `AUTH-3`), Dochi 캡처 API 연동, 트레이 상주 UI.

## 2026-09-24 — 코어 연동: 실제 로그인·캡처 API·대시보드 URL

- 대시보드 웹뷰가 플레이스홀더(`google.com`) 대신 실제 배포 주소(`https://dochi-six.vercel.app/dashboard`)를 가리킨다.
- `CaptureApiService`가 api.md 계약대로 붙었다: `baseUrl`을 실제 값으로 채우고, 엔드포인트를 `/api/v1/captures`로 고치고, `mode`를 `create`/`complete` 문자열로 바꾸고, 이미지 파트에 `Content-Type: image/png`를 붙였다(넷 다 없으면 서버가 400을 낸다).
- **실제 로그인(`AUTH-3`)을 구현했다** — `AuthService`가 시스템 브라우저를 열어 `/auth/app/start`로 보내고, `dochi://auth/callback` 딥링크(`app_links`, `macos/Runner/Info.plist`에 스킴 등록)로 code를 받아 `/auth/app/token`과 교환하고, 세션을 macOS Keychain(`flutter_secure_storage`)에 둔다. 만료·401 시 한 번 갱신을 시도하고 실패하면 로그인 화면으로 되돌아간다. 플레이스홀더였던 `StorageService.loadIsLoggedIn`/`saveIsLoggedIn`은 삭제했다.
- 캡처 응답의 `outcome`/`created`/`completed`/`failure`를 실제로 파싱한다 — 전에는 `2xx`면 무조건 "성공"으로 봐서 "생성할 태스크가 없어요" 같은 정상적인 `failed` outcome도 성공으로 잘못 알렸다. `failure.code`는 절대 분기하지 않고 `message`를 그대로 띄운다(api.md §변경 규칙 — 새 코드가 예고 없이 늘 수 있다).
- 타임존 버그를 고쳤다 — `DateTime.now().timeZoneName`(`"KST"`)을 그대로 보내서 서버가 매번 `400 VALIDATION_FAILED`를 냈다. `/etc/localtime` 심볼릭 링크에서 IANA 이름(`Asia/Seoul`)을 읽도록 바꿨다(`StorageService.localIanaTimeZone`).
- 로그인 화면을 Tide 디자인 시스템에 맞춰 다시 그렸다 — Mist 배경, 그림자 없는 흰 카드, 인디고 버튼, 실제 워드마크 SVG(`tide-kit-v3.0/assets/brand/`에서 복사). 커스텀 폰트(Pretendard·Wanted Sans)는 `tide-kit-v3.0/flutter/`가 이 체크아웃에 없어 아직 시스템 폰트로 대체돼 있다.
- 대시보드 화면의 (dev용) 로그아웃 버튼을 없앴다. 지금은 웹뷰 안 dochi 자체 로그아웃(웹 세션만 지운다)이 유일한 경로다 — 앱 자체 세션까지 지우는 로그아웃이 필요해지면 별도로 만들어야 한다.

## 2026-09-24 — 백그라운드 상주, OS 알림, 웹뷰 Google 로그인

- **대시보드 웹뷰의 Google 로그인이 시스템 브라우저에서 열리게 했다** — Google이 임베디드 웹뷰 안의 로그인 시도를 그대로 막기 때문이다. `dochi-six.vercel.app`을 벗어나는 모든 내비게이션을 `NavigationDelegate`로 가로채 `url_launcher`로 외부 브라우저에 넘긴다(같은 호스트 안 이동은 웹뷰에 그대로 둔다). 단, 그렇게 완료한 로그인 세션 쿠키는 시스템 브라우저 쪽에 남지 웹뷰로 넘어오지 않는다 — 웹뷰 자체는 여전히 로그아웃 상태로 남는 별개 문제이고, 아직 손대지 않았다.
- **창을 닫아도, `⌘Q`로 꺼도 앱이 종료되지 않는다** — 전역 캡처 단축키가 창이 아니라 프로세스에 등록돼 있어서, 종료되면 단축키도 함께 죽는다(사용자 결정, 2026-09-24: 일반적인 Mac 앱 관례와 다르게 `⌘Q`도 의도적으로 종료하지 않는다). `AppDelegate.applicationShouldTerminateAfterLastWindowClosed`가 `false`를 돌려주고 `MainFlutterWindow.isReleasedWhenClosed = false`로 창 객체를 살려 두며, `applicationShouldTerminate`를 오버라이드해 `⌘Q`·Dock의 "Quit"까지 가로채 창만 숨긴다. Dock 아이콘을 다시 누르면 `applicationShouldHandleReopen`이 숨겨 둔 창을 되살린다.
  - 이제 앱을 실제로 끌 방법이 없어지므로, 앱 메뉴에 **"Quit Tide Completely"(⌘⌥Q)**를 코드로 추가했다 — 이것만 진짜 종료로 이어진다. 표준 "Quit Tide"(⌘Q) 항목의 문구는 그대로 두었다(더 이상 실제로 종료하지 않지만, XIB를 손대지 않고는 라벨을 못 바꾼다).
- **캡처 결과를 macOS 알림(Notification Center)으로 띄운다** — 창이 닫혀 있으면 인앱 스낵바는 아무도 못 본다. `flutter_local_notifications`로 교체했고(`NotificationService`), 첫 실행에 알림 권한을 요청한다. 여러 건이 생성되면 그만큼 알림도 여러 개 뜬다(`api.md`의 "건마다 알림" 그대로).

## 2026-09-24 — 재서명할 때마다 권한을 다시 묻는 문제를 해결

`flutter build macos --release`는 ad-hoc 서명이라, 빌드할 때마다 macOS가 다른 앱으로 인식해 화면 기록·손쉬운 사용 권한을 매번 다시 물었다(TCC는 정체성을 코드 서명으로 구분한다). 처음엔 이 머신 로그인 키체인에 자체 서명 인증서("Tide Local Dev")를 만들어 매 빌드 뒤 수동으로 재서명하는 우회로 막았는데, 사용자가 Apple Developer 계정이 있다고 해서 더 나은 방법으로 바꿨다.

**진짜 원인은 따로 있었다.** 프로젝트 레벨 빌드 설정에 `CODE_SIGN_IDENTITY = "-"`(Flutter 기본 템플릿 값)가 박혀 있어서, Xcode에서 팀을 고르고 "Automatically manage signing"을 켜도 타겟의 `CODE_SIGN_STYLE = Automatic`을 이 값이 덮어써 계속 ad-hoc으로 서명됐다. 세 군데(Debug/Release/Profile 프로젝트 설정)에서 그 줄을 지우자 타겟 설정(`DEVELOPMENT_TEAM = WB5PG6BWM2`)이 제대로 먹혀 실제 "Apple Development" 인증서로 서명된다(`codesign -dv`의 `TeamIdentifier=WB5PG6BWM2`로 확인). 자체 서명 인증서는 이제 안 쓴다 — 진짜 팀 서명이 훨씬 안정적이고, 나중에 배포용 노터라이즈도 이 경로로만 가능하다.

## 2026-09-24 — Dock 아이콘 대신 메뉴바 트레이 아이콘

앱이 완전히 종료된 상태에서는 단축키를 쓸 방법이 원천적으로 없다(등록해 둘 프로세스 자체가 없으므로). 대신 로그인 시 자동 실행 얘기가 나왔고, 그러려면 "떠 있는지 한눈에 알 수 있어야 한다"는 요구가 붙어 Dock 아이콘의 대안으로 메뉴바 트레이 아이콘을 만들었다 — `tide-kit-v3.0/flutter-porting-guide.md`가 원래 그리던 방향이기도 하다.

- `Info.plist`에 `LSUIElement = true`를 넣어 Dock 아이콘과 Cmd+Tab 노출을 없앴다(`lsappinfo`의 `type="UIElement"`로 확인).
- `tray_manager`로 메뉴바에 Tide 심볼 템플릿 아이콘(`tide-kit-v3.0/assets/tray/tide-menubar-template@2x.png`에서 복사, `isTemplate: true`라 다크 모드에서 OS가 알아서 흰색으로 바꾼다)을 달았다. 클릭하면 "Show Dashboard"(창을 되살림, `window_manager`)와 "Quit Tide Completely"(진짜 종료) 두 항목이 뜬다.
- Dock 아이콘이 없어지면서 기존의 "Dock 아이콘 클릭 → 창 복귀" 경로(`applicationShouldHandleReopen`)가 사실상 쓸모없어졌다 — 트레이의 "Show Dashboard"가 그 자리를 대신한다. 코드는 남겨 뒀다(해가 없고, Spotlight로 재활성화하는 드문 경우엔 여전히 도움이 될 수 있다).
- "Quit Tide Completely"는 여전히 네이티브(`AppDelegate.quitCompletely()`)에 있다 — Dart 쪽 트레이 메뉴 클릭은 새 메서드 채널(`com.dochi.tide/app`)로 그걸 부르기만 한다. 두 실행 경로(앱 메뉴의 ⌘⌥Q, 트레이 메뉴 클릭)가 같은 종료 로직을 공유한다.
- `tray_manager`·`window_manager`는 0.7.x/0.6.x대에 새 C++ 코어(`nativeapi`)로 다시 쓰여지는 중이라 API가 크게 바뀌었다 — 검증된 구식 API(`trayManager` 싱글턴, `TrayListener`)가 남아 있는 마지막 버전(`0.5.3`/`0.5.2`)에 고정했다. 나중에 올릴 때는 마이그레이션 가이드를 먼저 읽는다.

## 2026-09-25 — Windows 지원: 두 번째 데스크톱 타깃

macOS 전용이던 앱에 Windows 빌드를 붙였다. `flutter create --platforms=windows .`로 러너를 만들고, macOS 전용으로 짜여 있던 부분을 플랫폼별로 갈랐다. **macOS 동작은 건드리지 않는 것을 제약으로 두었다** — 기존 코드는 그대로 두고 Windows 분기를 더하는 방향으로만 작업했다.

- **대시보드 웹뷰를 플랫폼별로 나눴다.** `webview_flutter`에는 Windows 구현이 아예 없다(Android/iOS/macOS만). `webview_windows`(Edge WebView2)를 더하고 `DashboardScreen`이 런타임에 둘 중 하나를 고른다. 조건부 import(`dart.library.*`)로는 못 가른다 — macOS와 Windows 둘 다 `dart:io`라 구분이 안 되기 때문이다. 그래서 `Platform.isWindows` 분기로 갔고, 두 구현이 양쪽 플랫폼에서 다 컴파일된다(`webview_windows`의 Dart 코드는 순수 Flutter 의존뿐이라 macOS에서도 빌드는 된다).
  - ⚠️ **off-host 내비게이션 처리 방식이 다르다.** macOS는 `NavigationDelegate`로 이동을 *막고* 외부 브라우저로 넘기지만, WebView2에는 "이동할까요?" 훅이 없다. Windows 쪽은 `url` 스트림으로 *이미 시작된* 이동을 감지해 `stop()` 후 되돌리므로, 외부 URL이 잠깐 비칠 수 있다. 기능은 같고 체감이 다르다.
- **전역 단축키를 `Ctrl+Shift+1/2`로 바꿨다(Windows 한정).** `HotKeyModifier.meta`는 Windows에서 Windows 키인데, `Win+Shift+숫자`는 셸이 "작업 표시줄 N번째 앱 새 인스턴스"로 이미 쓰고 있다. macOS는 `⇧⌘1/2` 그대로다. 배지 표기도 갈랐다 — `⌘`/`⇧` 글리프는 Mac 관례라 Windows에선 `Ctrl`/`Shift` 글자로 쓴다.
- **딥링크(`dochi://auth/callback`)를 런타임 레지스트리 등록으로 옮겼다.** macOS는 `Info.plist`의 `CFBundleURLTypes`로 정적 선언하면 끝이지만, Windows엔 그런 매니페스트가 없고 실행 파일의 절대 경로를 적어야 해서 설치 후에야 알 수 있다. `UrlSchemeService`가 매 실행마다 `HKCU/Software/Classes/dochi`에 다시 쓴다(HKCU라 권한 상승 불필요, 실행 파일을 옮겨도 따라간다).
  - 단일 인스턴스 처리가 같이 필요했다 — 링크를 누르면 exe가 새로 뜨는데, 로그인 플로가 기다리는 스트림과 전역 단축키는 *기존* 프로세스에 있다. `main.cpp` 맨 앞에서 `SendAppLinkToInstance()`를 불러 이미 뜬 인스턴스로 URL을 넘기고 새 프로세스는 바로 끝낸다.
- **트레이 아이콘은 Windows 전용 `.ico`를 쓴다.** macOS의 `tide-menubar-template.png`는 OS가 알아서 반전시키는 템플릿 이미지라, 그런 반전이 없는 Windows에선 검은 얼룩으로만 보인다. 클릭 관례도 갈랐다(Windows는 좌클릭=열기 / 우클릭=메뉴, macOS는 양쪽 다 메뉴). "Quit Tide Completely"도 macOS는 `AppDelegate`로 넘기지만 Windows엔 그게 없어 `windowManager.destroy()`를 쓴다.
- **타임존은 `flutter_timezone`으로 가져온다(Windows 한정).** Windows는 자체 zone id(`Korea Standard Time`)를 쓰는데 캡처 API는 IANA 이름을 요구한다. CLDR 매핑 표를 들고 있기는 아까워서 플러그인에 맡겼다. macOS의 `/etc/localtime` 경로는 그대로 뒀다 — 이미 돌아가는 걸 바꿀 이유가 없다.
- **Windows에선 클립보드 복사를 하지 않는다.** `screen_capturer`가 Windows에서 `ms-screenclip://`(캡처 도구)로 캡처하는데, 그 결과를 *클립보드를 통해* 돌려받는 구조다(클립보드를 비우고 → 스니핑을 기다렸다가 → 클립보드를 PNG로 저장). 즉 캡처가 끝난 시점에 이미 클립보드에 들어 있다. 굳이 다시 복사하면 중복인 데다, `powershell`은 콘솔 바이너리라 캡처할 때마다 검은 창이 깜빡인다.
- **앱 아이콘을 만들었다.** 트레이용 `.ico`는 32px까지뿐이라 작업 표시줄/탐색기에서 뭉개진다. `tide-tray-windows.svg`를 헤드리스 Edge로 16~256px 8종으로 굽고 ICO로 묶어 `windows/runner/resources/app_icon.ico`를 갈아 끼웠다(Flutter 기본 로고 대체).

### 함정 두 가지

- 🔑 **`window_manager`의 `setSkipTaskbar`를 `waitUntilReadyToShow` 없이 부르면 프로세스가 죽는다** (`0xC0000005`). 그 플러그인이 `ITaskbarList3`를 만드는 곳이 **오직** 네이티브 `WaitUntilReadyToShow()`뿐이라, 건너뛰면 널 포인터를 역참조한다. 우아하게 실패하지 않고 그냥 크래시하므로, Windows 창 설정은 전부 `waitUntilReadyToShow`를 통해야 한다. 실제로 첫 빌드가 이걸로 즉사했다.
- 🔑 **Windows 빌드에는 개발자 모드가 켜져 있어야 한다.** Flutter가 플러그인을 심볼릭 링크로 엮는데 Windows는 심볼릭 링크 생성에 권한이 필요하다. 꺼져 있으면 `flutter build`뿐 아니라 `pub get`·`analyze`·`test`까지 전부 `Building with plugins requires symlink support`로 멈춘다. 설치 요건은 `README.md`에 적어 뒀다.

검증한 것: `flutter analyze` 무결, 테스트 5개 통과(단축키 테스트는 플랫폼별로 기대값을 갈랐다), 릴리스 빌드 성공, exe 기동 후 상주 확인, `dochi://` 레지스트리 등록과 단일 인스턴스 전달 동작 확인(링크를 열어도 새 프로세스가 생기지 않음), 창 제목·앱 아이콘·로그인 화면 렌더 확인.
**아직 사람 눈으로 확인하지 않은 것**: 트레이 아이콘의 실제 모양과 메뉴, 작업 표시줄에서 숨겨졌는지, 전역 단축키로 캡처→업로드가 실제로 도는지, 로그인 왕복 전체. Windows 머신에서 한 번 직접 돌려봐야 한다.

## 2026-09-25 — Windows에서 안 되던 네 가지: 빈 대시보드·캡처·비밀번호 보기·Google 로그인

Windows에서 쓰다 보니 드러난 문제들을 한 번에 잡았다. 넷 다 실제로 앱을 띄우고 화면을 찍어 확인했다.

- 🔴 **대시보드가 늘 흰 화면이었다.** `webview_windows`는 WebView2를 Flutter 텍스처에 그려 넣는 방식인데, Windows 11 + 요즘 WebView2 런타임 조합에서 그 텍스처가 갱신되지 않는다 — 페이지는 멀쩡히 살아 있어서(`executeScript`로 `location.href`·DOM 크기를 찍어 확인했다) 로그만 보면 정상으로 보이는데, 창에는 순백(`255,255,255`)만 나왔다. 페이지 배경을 빨강으로 바꿔도 화면이 그대로인 걸로 텍스처가 죽었다고 확정했다.
  - **`webview_win_floating`으로 갈아탔다.** 텍스처가 아니라 진짜 WebView2 창을 Flutter 창 위에 얹는 방식이라 렌더링 경로 자체가 없다. 게다가 이 패키지는 `webview_flutter`의 *Windows 구현*으로 등록되므로(`implements: webview_flutter`), macOS(WKWebView)와 Windows가 같은 `WebViewController` API를 쓴다 — `dashboard_view_macos.dart`와 `dashboard_view_windows.dart`를 지우고 `dashboard_view.dart` 하나로 합쳤다.
  - ⚠️ 대가: Windows에선 **웹뷰 위에 Flutter 위젯을 그릴 수 없다**(네이티브 자식 창이므로). 권한 배너 같은 건 Windows에선 가려진다고 보면 된다.
- 🔴 **캡처가 서버까지 가지 않았다.** `screen_capturer`는 `ms-screenclip://`로 캡처 도구를 띄운 뒤 **1초 있다가** 포그라운드 창이 `SnippingTool.exe`인지 보고 "아직 캡처 중"을 판정한다. 캡처 도구가 처음 뜰 때는 1초를 넘기는 일이 흔해서, 사용자가 드래그를 시작하기도 전에 "끝났다"고 보고 빈 클립보드를 읽고 실패로 끝났다 — 캡처 도구의 알림만 뜨고 Tide는 아무 말이 없던 게 이 때문이다.
  - `ScreenshotService`가 직접 오버레이를 띄우고 **클립보드를 폴링한다**(먼저 비우므로 그 뒤에 나타나는 이미지는 이번 캡처가 맞다, 최대 90초). 프로세스 이름 대신 결과물을 기다리니 경합이 없다.
  - `capturedAt`이 오프셋 없는 ISO 문자열(`2026-09-25T18:00:00.000`)로 나가고 있었다 — api.md는 오프셋이 붙은 값을 요구한다. UTC(`Z`)로 보낸다.
  - 캡처가 성공하면 대시보드 웹뷰를 다시 읽는다(`DashboardRefresh`). 전에는 서버에 태스크가 생겨도 창에 떠 있는 목록은 캡처 전 그대로였다.
- **비밀번호 보기 버튼이 안 먹었다.** dochi 로그인 폼에는 보기 버튼이 없다 — 사용자가 누르던 건 Edge가 비밀번호 칸에 그려 주는 기본 버튼(`::-ms-reveal`)인데, WebView2에선 그려지기만 하고 동작하지 않는다(브라우저 셸 UI라 임베디드 컨트롤이 연결하지 않는다). 그 버튼을 숨기고 동작하는 "보기/숨기기" 토글을 dochi 호스트 페이지에만 주입한다. 입력 요소를 **옮기지 않고** 형제로 덧붙인다 — React가 추적 중인 노드를 재부모화하면 예외가 나면서 페이지가 통째로 비어 버린다.
- 🔴 **웹뷰 안 Google 로그인이 중간에 시스템 브라우저로 튕겼다.** Windows 쪽은 허용 호스트 목록(`dochi` / `accounts.google.com` / `*.supabase.co`)을 벗어나는 이동을 잡아 외부 브라우저로 넘기고 있었는데, Google 로그인은 그날그날 다른 호스트(기기 확인·동의 화면·캡차)를 거친다. 목록에 없는 첫 호스트에서 플로가 뜯겨 나가고, 쿠키도 OAuth 상태도 없는 브라우저는 그대로 멈춘다 — "verify it's you 뜨고 앱 창이 떴는데 더 안 나간다"가 이것이다.
  - **Windows에선 내비게이션을 가로채지 않는다.** WebView2는 Edge이고 Edge로 보이므로 Google이 막지 않는다(실제로 앱 창 안에서 Google 로그인 화면까지 확인했다). 밖에서 로그인해 봐야 쿠키가 브라우저에 남아 웹뷰는 계속 로그아웃 상태인, 원래 목적과 정반대인 결과만 나온다.
  - macOS는 규칙을 그대로 둔다 — WKWebView는 Google이 임베디드 웹뷰로 알아보고 아예 거부한다.
- **Windows 단축키 배지를 `Ctrl ⇧ 1`로 바꿨다.** `Shift`를 글자로 쓰면 배지가 세 칸짜리 단어 줄이 된다. `⇧`는 Windows 자신도 쓰는 기호라 Mac 관례인 `⌘`/`⌥`/`⌃`와는 사정이 다르다.
- **진단 로그(`AppLog`)를 더했다.** `%APPDATA%\com.example\ttabong\tide.log`에 실행·캡처·업로드·웹뷰 이동이 한 줄씩 쌓인다. GUI 빌드는 콘솔이 없어서 `debugPrint`가 어디에도 남지 않는다 — 브라우저나 사람 손이 있어야 재현되는 두 플로(로그인·캡처)를 이것 없이 디버깅할 방법이 없었다. 기존 `AuthService`의 `auth.log`도 여기로 합쳤다.

## 2026-09-25 — Windows 배포용 설치 프로그램

`Release` 폴더(69MB, DLL 15개 + `data\`)를 그대로 건네는 대신 단일 `Tide-Setup-1.0.0.exe`(10.2MB)를 만든다. Inno Setup 스크립트는 `windows/packaging/tide.iss`, 산출물은 `.dist-scratch/windows/`(gitignore됨)에 떨어진다. 빌드 방법은 `README.md`에 있다.

- 실행 파일 메타데이터의 `FileDescription`을 `ttabong` → `Tide`로 바꿨다(작업 관리자·파일 속성에 보이는 이름). `CompanyName`/`ProductName`은 일부러 그대로 뒀다 — 그 둘이 `%APPDATA%\<회사>\<제품>` 경로를 정하므로, 바꾸면 저장된 세션과 로그가 다른 곳으로 옮겨 가 사용자가 다시 로그인해야 한다.

## 2026-09-25 — 코어 전달 사항 반영 (되돌리기 · 히스토리 주소 · 태그 합치기 · 중복 감지)

dochi 쪽에서 넘어온 통지문 네 건을 훑고, 앱이 실제로 할 일만 했다. **넷 다 더하는 변경이라 기존 경로·필드·에러 코드는 하나도 바뀌지 않았다.**

- 🔴 **중복 감지(`DUPLICATE_TASK`·`duplicates[]`)는 고칠 게 없었다 — 그게 핵심이다.** 캡처 응답 파서가 `failure.code`로 분기하지 않고 `message`를 그대로 띄우게 돼 있어서, 전부 중복인 경우(`outcome: "failed"`)는 손대지 않아도 서버가 써 준 "이미 있는 태스크예요: …"가 그대로 알림으로 뜬다. 예고된 대로 동작한다는 걸 확인만 하고 끝낼 수도 있었지만, **그 성질을 테스트로 못 박았다**(`test/capture_notifications_test.dart`) — 모르는 코드가 와도 `message`가 나오는지까지 포함해서. 코드 목록을 검사하는 테스트를 쓰면 그게 곧 버그라, 일부러 그렇게 쓰지 않았다.
- **일부만 중복인 경우에 알림을 한 건 더 띄운다.** 통지문은 "조용히 넘어가도 틀린 동작은 아니다"라고 했지만, 세 개 잡아 캡처했는데 알림이 하나만 뜨면 나머지가 어디 갔는지 알 길이 없다. `duplicates`가 차 있고 `failure`가 없을 때만 붙는다(전부 중복인 경우는 위 `message`가 이미 말해 준다).
- **알림을 누르면 그 처리 기록이 열린다(`NTF-4`).** 통지문이 준 `/history?log=<jobLogId>`를 쓴다. `jobLogId`는 캡처 응답이 이미 주던 값인데 그동안 버리고 있었다 — `CaptureUploadResult`가 들고 있다가 알림 payload로 싣고, 클릭하면 창을 띄우면서 대시보드 웹뷰를 그 주소로 보낸다(외부 브라우저가 아니라 앱 안이다 — 통지문도 웹뷰로 열리는 경우를 전제한다).
  - `DashboardRefresh`를 `DashboardNavigation`으로 넓혔다. "새로고침"만 하던 채널이 이제 "이 주소를 띄워라"를 나른다 — 캡처 뒤 목록 갱신과 알림 클릭이 같은 배선을 쓴다.
  - URL은 `dochi_config.dart` 한 곳으로 모았다(`dashboardUri`·`historyUri`). `screens/dashboard_url.dart`는 지웠다 — services가 screens를 import하는 방향을 만들지 않으려고.
  - Windows 토스트를 실제로 눌러서 확인했다 — `[Notification] clicked, payload=c6afc6fa-…` 다음 `[Dashboard] navigating to …/history?log=c6afc6fa-…`가 찍힌다.
  - 🔑 **이동 로그는 `loadRequest` *전에* 남긴다.** 웹뷰가 로그아웃 상태면 dochi가 어느 주소든 `/login`으로 돌려보내서, 도착지만 찍으면 앱이 *어디로 가려 했는지*를 알 수 없다 — 히스토리로 갔는지 대시보드로 갔는지가 로그에서 똑같이 보인다. 통지문이 말한 정상 동작이지만, 그 탓에 검증이 한 번 헛돌았다.
- **되돌리기(`revertable`·`POST /job-logs/:id/revert`·에러 코드 둘)는 손대지 않았다.** 통지문 자신이 "되돌리기 버튼은 P2"라고 못박았고, 앱은 `/job-logs`를 아직 부르지도 않는다. 계약이 서 있다는 통지로만 받는다.
- **태그 합치기는 해당 사항이 없다.** 앱에 태그를 읽거나 캐시하는 코드가 없다.

## 2026-09-25 — 로그인 화면 손보기 (웹뷰 주입)

둘 다 dochi 쪽 페이지를 고치는 게 아니라 **앱 웹뷰에 주입하는 스크립트**로 처리했다. 이 저장소는 dochi 소스를 건드릴 수 없고, 두 문제 모두 "웹뷰 안에서만" 생기는 것이기도 하다.

- **"← 대시보드로" 링크를 감춘다.** 앱에서는 웹뷰가 *대시보드로* 출발했다가 세션이 없어서 이 화면으로 밀려온 것이라, 그 링크는 같은 자리로 되돌아올 뿐이다. `/login`·`/signup`·`/reset-password`에서만 감춘다.
- **'보기' 텍스트를 눈 아이콘으로 바꾸고 누르고 있는 동안만 보이게 했다.** 위치를 라벨 아래쪽에 붙이고 있었는데, 라벨은 캡션 텍스트까지 품고 있어서 "bottom"이 입력칸 한가운데와 전혀 다른 자리였고 폰트가 로드되면 더 밀렸다 — 이제 입력칸 자신의 `offsetTop`·`offsetHeight`로 잡고 `ResizeObserver`로 따라간다.
  - 토글이 아니라 **누름 유지**다(`pointerdown` → 보임, `pointerup`/`pointerleave`/창 `blur` → 가림). 손을 떼면 반드시 가려지므로 "켜 둔 걸 잊고 자리를 뜨는" 경우가 없다. `pointerdown`에서 `preventDefault()`를 불러 입력칸의 커서 위치를 빼앗지 않는다.
  - 주입 범위를 Windows 한정에서 양 플랫폼으로 넓혔다. WKWebView에는 애초에 기본 보기 버튼이 없어서 macOS에도 없던 기능이고, `::-ms-reveal` CSS는 WebKit에서 그냥 무시된다.
- ⚠️ **DOM을 옮기거나 지우지 않는다** — 버튼은 덧붙이고 링크는 `display:none`으로 감출 뿐이다. React가 추적 중인 노드를 재부모화하거나 삭제하면 예외가 나면서 페이지가 통째로 비어 버린다.

## 2026-09-25 — Windows 작업 표시줄로 돌아오기

창이 작업 표시줄에도 Alt+Tab에도 없어서, 다른 프로그램을 띄우면 Tide 창이 그 뒤로 사라지고 다시 찾아올 길이 없었다.

- **`skipTaskbar`를 뺐다.** macOS의 `LSUIElement`(Dock 아이콘 제거)를 Windows에 그대로 옮긴 결정이었는데, 두 플랫폼에서 뜻이 다르다 — 트레이는 *닫아 둔* 앱을 찾는 곳이지 지금 보고 있는 창을 다시 불러오는 곳이 아니다. 트레이 아이콘은 그대로 둔다(창을 닫은 뒤 되살리는 유일한 경로다). macOS는 건드리지 않았다.

"제거해도 `%LOCALAPPDATA%\Programs\Tide`에 파일이 남아 새 릴리스 설치가 충돌한다"는 제보를 재현했다. **정확한 제보였고, 실제로 그 상태를 이 머신에서 잡았다.**

- **제거 시 `{app}` 폴더를 통째로 지운다.** 잠긴 파일 하나 때문에 폴더가 남으면, 레지스트리 항목은 이미 사라진 뒤라 **다시는 아무도 치우러 오지 않는다.**
- **설치 시 이전 `data\`를 먼저 지운다.** 이름이 바뀌거나 빠진 에셋이 남아 섞이지 않게. `{app}` 전체를 지우지는 않는다 — 웹뷰 프로필까지 날아가 업그레이드마다 대시보드에서 로그아웃된다.
- 확인: ① 망가진 잔존 폴더 + 구 버전 실행 중 상태에서 1.3.0 설치 → 깨끗하게 올라갔다. ② 앱을 켜 둔 채 제거 → 폴더·시작 메뉴·`dochi` 스킴·제거 목록이 전부 사라졌다.

SmartScreen 경고를 없애는 유일한 무료 경로가 Store다(MSIX는 Microsoft가 서명한다. EXE/MSI 제출은 여전히 인증서를 요구한다). 우려했던 것들을 패키지로 만들어 실제로 등록·실행해 확인했다.

| 우려 | 결과 |
|---|---|
| 읽기 전용 설치 폴더 → 대시보드 | ✅ 프로필 이전으로 해결 |
| 레지스트리 가상화 → `dochi://` 딥링크 로그인 | ✅ 런타임 쓰기는 **실제로 묻혔고**(HKCU가 옛 경로 그대로였다), 매니페스트 `windows.protocol` 선언이 동작 — 경쟁 등록보다 우선했다 |
| 전역 단축키·캡처 | ✅ 업로드 200, 대시보드 자동 새로고침 |
| 알림 | ✅ 패키지 AUMID로 전달 |

- 🔴 **`identity_name`은 자리표시자다.** Store에 내려면 Partner Center가 이름 예약 때 발급하는 실제 값으로 바꿔야 하고, **한 번 게시하면 바꿀 수 없다** — 바꾸면 다른 앱이 되어 기존 사용자가 업데이트를 못 받는다(Inno `AppId`와 같은 원리).
- 참고: Store 설치본은 SmartScreen 평판 게이트를 아예 타지 않으므로, 업데이트해도 "신뢰도 리셋" 같은 것이 없다.

## 2026-09-26 — 1.6.0: 웹뷰가 로그인 화면을 보지 않는다, 그리고 주입을 전부 지웠다

코어에서 전달 사항이 왔다. 넘겼던 넷이 전부 웹으로 넘어왔고, 요청한 적 없는 것 하나가 더 왔다 — 그게 이번 릴리스의 핵심이다.

### 앱 세션을 웹뷰로 잇는다 (`POST /api/v1/web-session`)

앱에는 로그인이 **두 벌** 있었다. 앱의 토큰과 웹뷰의 쿠키다. 둘을 잇는 것이 없어서, 앱에 로그인한 사용자가 **앱 안에서 웹 로그인 화면을 한 번 더** 만났다. macOS에서는 그 화면이 아예 끝나지 않았다 — 웹뷰가 Google 로그인을 시작하며 검증 쿠키를 웹뷰에 저장하는데, Google이 내장 웹뷰를 막아 흐름이 시스템 브라우저로 넘어가고, 거기엔 그 쿠키가 없어 **첫 시도가 반드시 실패**했다. 두 번째 시도는 성공하지만 로그인되는 건 브라우저였고 웹뷰는 끝까지 로그아웃이었다.

- 이제 웹뷰는 **URL로 페이지를 열지 않는다.** 경로를 `web-session`에 넘겨 **일회용 로그인 주소**를 받아 연다(`WebSessionService`). 앱 시작, 캡처 후 새로고침, 알림 클릭(`next=/history?log=…`) 전부 같은 통로를 쓴다.
- 웹뷰가 `/login`에 도착하면 **한 번만** 다시 시도한다. 무한 반복을 막는 것이 중요하다 — 반복은 그 자체로 일회용 주소를 계속 태운다.
- 🔑 **그 주소는 로그에 남기지 않는다.** 여는 사람을 로그인시키는 자격 증명이고, 로그 파일은 대화창과 버그 리포트로 옮겨 다닌다. 목적지 경로만 남긴다.
- 실패하면(500 등) 경로를 그대로 열고 웹 로그인 화면이 대신하게 둔다 — api.md가 지시한 그대로다.
- 확인: `[Dashboard] opening /dashboard` → `[WebSession] bridged to /dashboard` → `[Dashboard] loaded …/dashboard`. 전에는 여기가 `/login`이었다.

### 웹뷰 주입을 전부 지웠다

넘겼던 셋을 웹이 가져갔다 — 비밀번호 보기 토글, Windows 단축키 철자, `← 대시보드로` 링크. **주입 코드가 하나도 남지 않았다.** `page polish` 로그도 함께 사라졌다.

- 토글 방식은 우리와 다르다. 우리는 **누르고 있는 동안만**, 웹은 **누를 때마다 뒤집기**. 웹 쪽이 낫다 — 키보드만 쓰는 사람은 `Enter`를 누른 채 읽을 수 없다.
- 좁은 폭 문제는 **주입하지 않기로 했던 항목**이었고, 그 판단이 맞았다. 웹이 우리 제안(줄로 나누기)보다 나은 답(플랫폼 선택 버튼)을 냈고, CSS를 덮어쓰고 있었다면 그 개선과 충돌했을 것이다.

### 주소를 `tide-task.vercel.app`으로 옮겼다

옛 주소도 계속 동작하지만 옮겼다. **웹 로그인 쿠키는 호스트마다 따로**라 API와 웹뷰가 다른 호스트를 보면 로그인이 두 번 필요해진다 — 그래서 API 베이스·로그인 진입점·웹뷰를 **한꺼번에** 옮겼다. `web-session`이 돌려주는 주소도 요청한 호스트를 따라온다. 딥링크 스킴 `dochi://`는 그대로다(사용자에게 보이지 않고, api.md가 글자까지 일치를 요구한다).

### 로그에서 인증 코드를 가린다

딥링크 로그에 일회용 인증 코드가 평문으로 찍히고 있었다. 한 번 쓰면 무효화되지만, 로그는 붙여넣어져 돌아다니는 파일이라 자격 증명이 있을 자리가 아니다. `code=<redacted>`로 바꿨다 — 링크가 왔는지, 형식이 맞는지, state가 맞는지는 그대로 남는다.

### `handledAt`

작업 기록의 새 칸. 모르는 키를 무시하도록 파싱하고 있어 **할 일이 없었다.** 앱은 `/job-logs`를 아직 부르지도 않는다.

## 2026-09-26 — 1.7.0: 제거하면 정말 지워진다, 그리고 웹뷰가 없을 때 그렇게 말한다

제보 하나에서 시작했다. **계정을 지우고 다시 가입했더니 캡처가 안 된다. 앱을 지웠다 다시 깔아도, 다른 계정으로 바꿔도 마찬가지다.**

### 원인 — 앱에 로그아웃이 없다

앱에는 로그인이 두 벌이다. 캡처가 쓰는 **앱 토큰**과 대시보드가 쓰는 **웹 세션**이다. 사이드바의 `로그아웃`은 웹페이지의 버튼이라 웹 세션만 지운다. 앱 토큰을 버리는 코드는 딱 한 군데 — "갱신이 서버에서 거절당했을 때" — 에서만 불린다. 트레이 메뉴에도 로그아웃이 없다.

그래서 계정이 지워져도 앱 토큰이 그대로 남고, 그 토큰이 **다시 가입한 계정도 아니고 다른 계정도 아닌, 존재하지 않는 계정**을 계속 가리킨다. 세 증상이 전부 여기서 나온다:

- 재가입해도 안 됨 — 캡처는 앱 토큰으로 간다.
- 지웠다 깔아도 안 됨 — 토큰이 `%APPDATA%\Tide\Tide`에 있는데 **제거 프로그램이 그 폴더를 안 지웠다.** `{app}`과 `{localappdata}\Tide`만 지우고 있었다.
- 계정 B로 바꿔도 안 됨 — 계정 전환을 웹뷰 안에서 하면 웹 세션만 바뀐다.

설계상으로는 서버가 `401`을 주면 앱이 스스로 복구한다. 그 코드는 있고 동작한다. **한 번도 안 돌았다는 건 서버가 401을 주지 않았다는 뜻이고**, 그건 우리가 못 고친다 — `docs/20-Core-Requests.md`로 넘겼다.

### 고친 것

- **제거하면 `%APPDATA%\Tide`와 1.3.0 이하 경로(`com.example\ttabong`)까지 지운다.** "제거하고 다시 깔면 초기화된다"가 이제 참이다. 업그레이드에는 영향이 없다 — Inno는 덮어 설치할 때 이전 제거 프로그램을 돌리지 않으므로 `[UninstallDelete]`는 사용자가 실제로 "제거"를 눌렀을 때만 실행된다.
- **로그에 상한을 뒀다.** 1MB를 넘으면 뒤쪽 512KB만 남기고 자른다. 이 파일은 사적인 파일이 아니다 — 버그 리포트에 첨부돼 돌아다니고, **캡처가 만든 태스크 제목이 그대로 들어 있다.** 무한정 쌓이면 설치한 날부터의 기록을 전부 들고 있게 된다. 실제로 이 기계의 로그에는 1.3.0 시절 줄이 남아 있었고, 거기엔 1.6.0에서 가리기 시작한 인증 코드가 평문으로 들어 있었다.
- **WebView2가 없으면 그렇게 말한다.** 대시보드는 통째로 WebView2다. 런타임이 없으면 지금까지는 **설명 없는 흰 화면**이었다 — 앱이 망가진 건지, 로그인이 안 된 건지, 인터넷이 끊긴 건지 구분할 수 없었다. `webview_windows`를 쓰던 시절엔 이 확인이 있었는데 `webview_win_floating`으로 갈아타면서 사라졌고 그대로 잊혔다. 안내 화면 + 다운로드 링크 + "다시 확인"(런타임은 앱을 켜 둔 채 설치되므로 재시작 없이 알아차려야 한다)으로 복구했다.
  - 🔑 **탐지는 실패하는 쪽이 "있다"이다.** 읽을 수 없으면 있다고 본다. 거짓 음성이 훨씬 나쁘다 — 대시보드가 멀쩡히 되는 사람 앞에 "이것부터 설치하세요" 벽을 세우게 된다.
  - 버전 폴더가 아니라 **실행 파일**을 찾는다. `Application` 폴더에는 제거 후에도 남는 `SetupMetrics`가 있어서, "하위 폴더가 있으면 설치된 것"으로 보면 런타임이 없는 기계에 있다고 답한다.

### 넘긴 것

- **삭제된 사용자의 토큰에는 401을** — 되면 사용자가 아무것도 안 해도 앱이 알아서 로그인 화면으로 돌아온다.
- **사용자가 직접 로그아웃한 것을 앱도 알 수 있게** — 사이드바 로그아웃이 앱 로그인까지 끊도록.

트레이에 로그아웃을 따로 다는 방안은 **접었다.** 이름이 같은 버튼이 두 군데 있고 하는 일이 다르면 사용자가 구분할 수 없다. 고칠 자리는 보이는 버튼 하나가 제대로 동작하게 만드는 쪽이다.

## 2026-09-27 — 1.8.0: 보이는 로그아웃이 진짜 로그아웃이 된다

코어가 2026-09-26에 넘긴 두 건을 반영해서 회신했다. 둘 다 확인했고, 딸려 온 세 번째 건에서 **저쪽이 "앱이 할 일 없다"고 본 것이 틀렸다는 것**을 찾았다.

### `/login?signedOut=1` — 사용자가 로그아웃하면 앱도 로그아웃한다

웹이 **직접 로그아웃**과 **세션 만료**를 구분되는 주소로 갈라 줬다. 탈퇴도 같은 주소로 끝난다.

그전까지 앱은 둘을 구분할 수 없어서 전부 "만료"로 보고 **다시 이어 붙였다**. 그래서 사이드바 `로그아웃`을 누르면 앱이 일회용 주소로 웹뷰를 **방금 나온 계정에 도로 로그인**시켰다. 캡처 단축키는 애초에 앱 토큰을 쓰므로 계속 그 계정으로 올라가고 있었다. 공용 PC에서 로그아웃하고 자리를 뜨는 경우를 생각하면 곤란한 동작이었다.

- 이제 `signedOut=1`이 보이면 **`web-session`을 부르지 않고** 앱 토큰을 지운 뒤 앱 로그인 화면으로 간다.
- 🔑 **로그에 쿼리를 쓰지 않는다.** 이 자리에 도착하는 주소 중 하나가 브리지의 일회용 로그인 주소이고, 그 쿼리는 자격 증명이다. 표시가 필요한 한 가지만 이름으로 붙인다(`(signed out)`).
- 서버의 앱 세션은 이 신호로 끊기지 않는다 — 웹 로그아웃은 그 웹뷰의 세션만 닫는다. 다른 PC의 앱까지 끊지 않으려는 저쪽의 의도적 설계다.

### 서버가 거절 이유를 말하면 그대로 띄운다

새로 생긴 `403 CONSENT_REQUIRED`(개인정보처리방침 동의 전 계정)를 계기로 드러났다. 저쪽은 "모르는 코드가 오면 `message`를 그대로 띄우는 기존 규칙이 이미 처리한다"고 봤는데, **그 규칙은 `200` 응답 안의 `failure.message`에만 걸려 있었다.** HTTP 오류 상태는 다른 길로 갔고, 그 길 끝에서 앱이 서버 문구를 버리고 `"캡처를 보내지 못했습니다"`로 덮어쓰고 있었다.

| | 떠야 할 것 | 뜨던 것 |
|---|---|---|
| 동의 전 계정의 캡처 | 개인정보처리방침 동의가 필요합니다. Tide 대시보드를 열어 동의해 주세요. | 새 태스크 캡처를 보내지 못했습니다. |

무엇을 해야 하는지가 사라져 있었다. 고치면서 **서버가 말한 거절**과 **우리 쪽에서 깨진 것**을 갈랐다 — 앞의 것만 화면에 나가고, 뒤의 것(`SocketException` 같은 기술 문구)은 로그에만 남는다. `403`뿐 아니라 앞으로 생길 모든 오류 코드가 같이 덮인다.

`401`과 섞지 않는 것(갱신도 로그아웃도 하지 않음)은 원래부터 맞게 돼 있었다.

### 확인만 한 것

- **삭제된 계정의 `401`** — `api.md` 정본에서 옛 문장("탈퇴해도 `401`은 오지 않는다")이 반대로 바뀐 것을 확인했다. 앱에 넣을 코드는 없다. 실제로 삭제된 계정이 `401`을 받는지는 계정을 지워 봐야 알 수 있어 **확인하지 못했다.**
- **에러 봉투 모양** — `{"error":{"code","message"}}`가 그대로다. 토큰 없이/위조 토큰으로 `/api/v1/me`를 불러 확인했다.

### 넘긴 것

- **개인정보처리방침에 국외 이전 조항이 없다.** 게시된 방침 12개 조 어디에도 `국외`·`해외`·`미국`·`거부`가 나오지 않는데, 위탁 표의 넷은 전부 미국 법인이다. 제5조의 "탈퇴 즉시 전부 삭제·복구되지 않음"도 국외 수탁사의 백업·보유 정책까지는 보증할 수 없다.

### MSIX — Store 이름과 이후 배포

- **`display_name`을 `Tide AI`로 맞췄다.** Partner Center에 예약한 이름과 글자까지 같아야 업로드가 통과한다. `identity_name: Tide.TideAI`가 그 이름에서 파생된 값이다.
- **`output_name`을 고정했다.** 안 두면 파일 이름이 `display_name`을 따라가서, Store 이름이 바뀔 때마다 릴리스 절차의 경로가 같이 바뀐다.
- **이제부터 모든 릴리스에 MSIX를 같이 만든다.** `pubspec`의 `version:` 하나만 고치면 설치 프로그램과 MSIX가 같은 번호로 따라온다(1.7.0에서 자동화).

## 2026-09-27 — 1.8.1: 알림에 Tide 아이콘이 나온다

Windows 토스트에 아이콘이 없었다. 캡처할 때마다 앱 마크 자리가 빈 사각형이었다.

Windows는 토스트 아이콘을 **디스크의 파일 경로**에서 읽는다 — 바이트를 건네줄 방법이 없다. 그런데 Flutter 에셋은 번들 안에 있어서 셸이 따라 들어가지 못한다. 그래서 실행할 때 아이콘을 `%LOCALAPPDATA%\Tide\notification-icon.png`로 꺼내 쓰고, 그 경로를 알림 초기화에 넘긴다.

- 확인: 실행 뒤 `HKCU\Software\Classes\AppUserModelId\com.tide.app`의 `IconUri`가 그 파일을 가리킨다. 이 값이 **원래는 아예 없었다** — 그게 아이콘이 안 나온 이유다.
- 매 실행마다 다시 쓴다. 빌드에 딸려 오는 파일의 사본이라, 이전에 잘못 쓰인 것이 스스로 고쳐지고 다음 버전에서 아이콘이 바뀌면 그대로 갈린다.
- 꺼내기가 실패하면 `null`을 넘긴다 — 아이콘만 없던 예전 상태로 돌아갈 뿐, 알림 자체를 잃지 않는다.
- 지우는 것은 제거 프로그램이 `%LOCALAPPDATA%\Tide`를 통째로 지우면서 같이 된다.

MSIX 쪽은 `logo_path`에서 만들어진 타일 로고가 이미 패키지에 들어 있고(`Square44x44Logo` 외), 토스트용 에셋도 함께 실린다. **다만 MSIX로 설치해 실제 토스트를 본 적은 없다 — 미확인.**

**이것만으로는 안 나왔다.** 1.8.2에서 마저 고쳤다.

## 2026-09-27 — 1.8.2: 알림 아이콘을 실제로 띄워 보고 고쳤다

1.8.1에서 아이콘 경로를 등록했는데도 알림에 아이콘이 안 나왔다. 이번에는 **실제로 토스트를 띄워 화면으로 확인**하면서 고쳤다(단축키를 눌러 영역을 드래그하고, 알림이 뜨는 우하단을 1.2초 간격으로 연속 촬영했다).

빠져 있던 것은 **바로 가기의 앱 ID**였다. 포장되지 않은 Win32 앱은 알림 머리줄의 이름과 아이콘을 실행 중에 지정할 수 없다 — Windows가 시작 메뉴에서 앱 ID를 찾아, 그 바로 가기에서 가져간다. 바로 가기에 ID가 없으면 찾을 것이 없어서 빈 사각형이 된다. 설치 스크립트가 `AppUserModelID`를 바로 가기에 찍도록 했다.

그리고 **토스트에는 Tide 마크가 두 개 들어간다는 것**을 알게 됐다. 둘은 같은 그림이 아니어야 한다:

| 자리 | 쓰는 그림 | 어디서 오나 |
|---|---|---|
| 머리줄(앱 이름 왼쪽) | `tide-symbol-reverse` — 밝은 원 안에 물결 | 앱이 실행할 때 파일로 꺼내 둔 경로, 바로 가기의 앱 ID를 통해 |
| 본문 왼쪽(큰 로고) | 앱 아이콘 | 알림 자체가 들고 간다(`appLogoOverride`) |

머리줄은 토스트의 어두운 크롬 위에 얹히므로 **reverse 심벌**을 쓴다. 본문 로고는 알림에 딸려 가므로 등록 상태와 무관하게 나온다 — Windows가 앱의 등록 아이콘을 꽤 오래 캐시하기 때문에, 이쪽이 더 확실한 경로다.

- 본문 로고의 경로는 플러그인 헬퍼가 만들어 주지만, 그 헬퍼는 파일 경로를 **작업 디렉터리** 기준으로 만든다. `dochi://` 링크로 실행되거나 터미널에서 뜨면 그 디렉터리가 실행 파일 폴더가 아니다. 그래서 파일인 경우만 `Platform.resolvedExecutable`에서 다시 만든다(패키지 안에서는 `ms-appx:`라 그대로 쓴다).
### 머리줄 심벌은 Windows 테마를 따라 두 벌이다

토스트 크롬이 Windows 테마를 따라가므로, 한 장으로는 한쪽에서 반드시 안 보인다. reverse 심벌(거의 흰 원)은 **밝은 토스트 위에서 사라지고**, 보통 심벌(인디고 원)은 어두운 토스트 위에서 탁해진다. 그래서 `SystemUsesLightTheme`를 읽어 갈라 쓴다.

- 🔑 **`SystemUsesLightTheme`이지 `AppsUseLightTheme`이 아니다.** Windows가 설정을 둘로 쪼개 뒀는데, 앞의 것이 작업 표시줄·알림 센터·토스트를 칠하고 뒤의 것이 앱 창을 칠한다. 토스트는 앞쪽이다.
- 읽지 못하면 **밝은 테마로 친다.** 흔한 쪽이 아니라 안전한 쪽이다 — 인디고 원은 어느 배경에서나 읽히지만 reverse는 어두운 배경에서만 읽힌다. 이 방향으로 틀리면 아이콘이 좀 탁할 뿐이고, 반대로 틀리면 **아예 안 보인다.**
- 트레이 앱이라 며칠씩 떠 있으므로 시작할 때 한 번으로는 부족하다. 알림을 띄울 때마다 테마를 다시 보고, 달라졌으면 **같은 경로에 내용만** 새로 쓴다. 등록을 다시 할 필요가 없다.
- 확인: 캡처 → 토스트 촬영을 **두 테마 모두**에서 했다. 어두울 때 머리줄에 밝은 원, 밝을 때 인디고 원, 본문에는 양쪽 다 앱 아이콘이 나온다. 테마를 바꾼 뒤 알림 한 번에 바로 갈린다(로그에 `theme changed — rewriting the toast icon`).
