# 00 — Overview

> 작성일 2026-09-19 · 뼈대 단계에서 정한 경계. 코드가 붙기 전에 읽는 문서다.

## 제품 구성

두 저장소가 하나의 제품을 이룬다.

| 저장소 | 역할 | 스택 |
|---|---|---|
| `lianist/ttabong` (이 저장소) | **플러그인 호스트 데스크톱 앱** | Flutter (macOS 우선) |
| `lianist/dochi` | **코어** — LLM · DB · 인증을 품고 API로 노출 | Next.js + Supabase |

Ttabong은 코어에 붙는 첫 번째 앱이다. 코어는 이 앱의 존재를 전제하지 않는다.

## 경계 (이 세 줄이 규칙이다)

1. **Supabase를 직접 호출하지 않는다.** Dochi가 노출하는 HTTP API만 쓴다.
   → 인증 · RLS · LLM 키가 코어 한 곳에 모이고, 데스크톱 바이너리에 비밀이 실리지 않는다.
2. **LLM 키를 앱이 들고 있지 않는다.** 모델 선택·프롬프트 조립은 코어 소관이다.
3. **플러그인 규약은 이 저장소 소관이다.** 매니페스트 형식과 호스트가 플러그인에 주는 API 표면을 여기서 정의한다.

## 플러그인 호스트 (설계 예정)

정해야 할 것:

- 매니페스트 형식과 최소 필드 (이름 · 버전 · 진입점 · 요구 권한)
- 플러그인 배포·설치 경로, 버전 호환 규칙
- 호스트가 주는 API 표면 — UI 슬롯, 저장소 접근, 코어 API 프록시
- 격리 수준 (같은 프로세스 vs 분리 실행)
